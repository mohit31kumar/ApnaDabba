# Plan: MiMo Code Team as OpenCode Relay Participants

## Goal
Create a MiMo Code team (tech-lead, architect, backend, frontend) that participates in the opencode-relay network alongside the existing OpenCode team. MiMo Code acts as a single coordinator managing 4 virtual bridge servers, one per role. Manual trigger for shift handoff.

## Architecture

```
┌─────────────────┐  ┌─────────────┐  ┌──────────┐  ┌───────────┐
│  OpenCode       │  │  OpenCode    │  │ OpenCode │  │ OpenCode  │

│                 │  │  :4001       │  │ :4002    │  │ :4003     │
└────────┬────────┘  └──────┬───────┘  └────┬─────┘  └─────┬─────┘
         │                  │               │              │

         ▼                  ▼               ▼              ▼
┌─────────────────────────────────────────────────────────────────┐
│                    MiMo Bridge Servers                           │
│  tech-lead :4004  │  architect :4005  │  backend :4006  │ frontend :4007 │
│  (inbox.jsonl)    │  (inbox.jsonl)    │  (inbox.jsonl)  │ (inbox.jsonl)  │

                            │
```

## Implementation Steps

### Step 1: Create Bridge Server Template (`relay-bridge/server.js`)

A reusable Node.js HTTP server that:
- Accepts `PORT` and `ROLE` as environment variables
- Exposes the OpenCode API surface the relay plugin expects:
  - `GET /global/health` → `{"healthy":true,"version":"mimo-bridge-1.0"}`
  - `GET /session?limit=N` → returns fake session with title matching ROLE
  - `POST /session/{id}/prompt_async` → writes message to `{ROLE}.inbox.jsonl`
- Uses only Node.js built-in `http` module (no dependencies)

### Step 2: Create Startup Script (`relay-bridge/start.sh`)

Launches all 4 bridge servers:
```bash
PORT=4004 ROLE=tech-lead node relay-bridge/server.js &
PORT=4005 ROLE=architect node relay-bridge/server.js &
PORT=4006 ROLE=backend node relay-bridge/server.js &
PORT=4007 ROLE=frontend node relay-bridge/server.js &
```

### Step 3: Create Send Script (`relay-bridge/send.sh`)

Usage: `./relay-bridge/send.sh <target> <message>`

Maps target names to ports:
- tech-lead → 4000, architect → 4001, backend → 4002, frontend → 4003 (OpenCode)
- Also supports sending to MiMo's own virtual team (4004-4007)

Resolves session ID via `/session?limit=10` and POSTs to `/session/{id}/prompt_async`.

### Step 4: Create Inbox Reader (`relay-bridge/read-inbox.sh`)

Usage: `./relay-bridge/read-inbox.sh [role]`

Shows messages from one or all inboxes. Without argument, shows all.

### Step 5: Update `opencode-relay.json`

Add 4 MiMo instances:
```json
{
  "instances": {
    "tech-lead":  { "port": 4000 },
    "architect":  { "port": 4001 },
    "backend":    { "port": 4002 },
    "frontend":   { "port": 4003 },
    "mimo-tech-lead":  { "port": 4004 },
    "mimo-architect":  { "port": 4005 },
    "mimo-backend":    { "port": 4006 },
    "mimo-frontend":   { "port": 4007 }
  }
}
```

### Step 6: Create Shift Handoff Script (`relay-bridge/handoff.sh`)

Usage: `./relay-bridge/handoff.sh`

When triggered:
1. Checks which OpenCode instances are still online via `/global/health`
2. Reads pending messages from all MiMo inboxes
3. Reports status: which OpenCode instances are offline, what messages are pending
4. MiMo Code then processes the pending work

## How It Works End-to-End

### Sending from OpenCode to MiMo
1. OpenCode instance runs `relay-connect` → discovers all 8 instances
2. OpenCode runs `relay-chat(target="mimo-tech-lead", message="Review the architecture")`
3. Relay plugin POSTs to `http://127.0.0.1:4004/session/{id}/prompt_async`
4. MiMo bridge server receives the message, writes to `mimo-tech-lead.inbox.jsonl`
5. MiMo Code reads the inbox and processes the request

### Sending from MiMo to OpenCode
1. MiMo Code runs `./relay-bridge/send.sh backend "Implement the auth middleware"`
2. Script fetches sessions from port 4002, finds backend session ID
3. Script POSTs to `/session/{id}/prompt_async` with the message
4. OpenCode backend instance receives and processes the message

### Shift Handoff
1. User runs `./relay-bridge/handoff.sh`
2. Script checks health of all OpenCode instances
3. Reports which are offline and what messages are pending
4. MiMo Code takes over processing the pending work
